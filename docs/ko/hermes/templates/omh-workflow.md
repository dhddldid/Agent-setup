## OMH 워크플로 사용

어떤 언어로 받은 작업이든 행동하기 전에 작업 형태에 맞춰 전체 흐름을 직접 고른다.
- 여러 부분을 순서대로 진행하거나 병렬로 처리할 작업은 `dag-ulw`를 쓴다.
- 승인된 계획을 여러 작업 라인으로 나누어 구현할 때는 `ulw-work`를 쓴다.
- 조사·구현·검증을 반복해야 하는 장기 목표에는 `ulw-loop`를 쓴다.
- 아직 결정되지 않았거나 위험이 큰 계획에는 `ulw-plan` 또는 `omh-plan`을 쓴다.
- 리뷰에는 `omh-code-review`를 쓴다.
- 범위가 작고 명확한 수정 하나는 바로 처리한다.
선택한 워크플로를 `skill_view`로 불러 절차를 따른다. 완료를 선언하기 전에는 `omh-verification-gate`를 불러 검증 기준을 따른다.

- 선택한 워크플로 안에서 개인·프로젝트 스킬의 프로젝트 규칙, 계정, 도구, 점검 기준을 적용한다. 각 노드와 작업 라인에서도 관련 스킬을 불러온다.
- 어떤 언어로 받은 여러 부분 작업이든 Route Hint를 기다리지 않고 `dag-ulw`와 `dag-ulw-notes`를 직접 불러온다. 이미 승인된 작업은 병렬 진행 승인을 따로 묻지 않고 바로 시작한다.
- OMH Route Hint나 스킬 후보 목록이 나오면 첫 행동 전에 제시된 스킬을 `skill_view`로 불러온다. 해당 절차를 따르거나 다른 워크플로가 맞는 이유를 한 줄로 설명한다.
- 매번 `delegate_task` 직전에 `omh_delegate_route`를 호출하고 라우팅 결과를 따른다.
- 세 단계 이상인 작업은 `omh_todo`에 기록하고 진행에 맞춰 갱신한다.
- 여러 에이전트를 쓰는 작업은 `omh_agent_board`로 진행 상황을 관리하고, 마칠 때 `omh_run_summary`로 기록된 시간과 토큰을 보고한다.
- 준비한 계획·인계 내용과 실제 실행·검증 결과를 구분해 보고한다.
- 사용자에게는 한국어로 보고한다.
